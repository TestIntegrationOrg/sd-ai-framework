## CI protocol

`.github/workflows/ci.yml` runs on pull requests and pushes to `main`, with four required legs:

- Ubuntu / Python 3.11
- Ubuntu / Python 3.12
- Windows / Python 3.11
- Windows / Python 3.12

Every leg executes the unfiltered `pytest -q` suite.

The release evidence sequence is:

1. freeze the focused #242 PR head;
2. require all four PR-head matrix jobs to pass and resolve all review threads;
3. squash-merge with the exact expected PR head SHA;
4. independently validate the exact squash-merged `main` SHA using the `push: main` CI run;
5. record the PR head, PR run, squash SHA, merged-main run, and four merged-main job results below;
6. only then close #242 and parent #26.

A successful PR run is not interchangeable with merged-main evidence.
