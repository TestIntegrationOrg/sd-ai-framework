This document is the concise release synchronization record for SDAI 1.0. It summarizes the identity-independent capability slices that have already passed their own exact-head implementation and evidence gates. It does not replace the detailed evidence documents for those slices.

## Release identity

- Framework/package version: **1.0.0**.
- Authoritative version source: `src/sdai/__init__.py::__version__`.
- `pyproject.toml` consumes that value dynamically; it must not duplicate a static package version.
- `sdai --version`, built wheel metadata, README release metadata, and generated `.sdai/framework-version.yaml` must resolve to the same authoritative value.
- Package maturity: **Production/Stable**.

## Release-blocking validation

The normal CI gate must remain unfiltered and run on all supported release legs:

- Ubuntu with Python 3.11 and 3.12;
- Windows with Python 3.11 and 3.12;
- macOS with Python 3.11 and 3.12.

Every leg runs the complete `pytest -q` suite and the isolated `tests/package_install_smoke.py` check. The package smoke builds a wheel, installs it into a fresh virtual environment outside the repository import path, invokes the installed CLI, exercises brownfield initialization and migration behavior, and proves rollback/preservation behavior.

Release metadata validation additionally fails CI when the README release marker/status, package maturity classifier, dynamic setuptools version source, or this release-readiness record drifts from the authoritative version.

The stable compatibility promise, SemVer/deprecation/security-exception rules,
candidate evidence, blockers, and separate publication boundary are defined in
`docs/COMPATIBILITY-AND-RELEASE-GOVERNANCE.md`.

## Compatibility posture

SDAI 1.0 freezes the public compatibility boundaries documented by the 1.0 stabilization slices. Package-version synchronization does **not** mechanically change independent schema, protocol, workflow, extension, evidence, or JSON `apiVersion` identifiers. Those contracts evolve only when their own compatibility semantics require a new version.

Upgrade remains conservative: team-owned content is preserved, only eligible SDAI-managed stock paths are changed, migration evidence is hash-bound, interrupted prepared transactions recover only from exact recorded states, and ambiguous/unknown bytes fail closed.

## Explicit held scope

**0.18/#25 identity-backed approvals remain held** and are not part of SDAI 1.0. The release must not claim GitHub Enterprise/OIDC/SSO identity verification, cryptographic approver identity, identity-backed authorization, or distinct-approver enforcement. Existing approval/audit/migration evidence is local integrity/provenance evidence unless a future explicitly authorized scope adds identity verification.

## Release cut rule

A 1.0 release candidate is acceptable only when the exact frozen pull-request head has zero unresolved actionable review threads and all six supported OS/Python CI jobs pass the full historical suite plus the isolated wheel-install smoke. Publishing a package or creating a tag is a separate explicit release action; this repository synchronization work does not claim that publication has occurred.
