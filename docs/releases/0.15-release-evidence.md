# SD-AI 0.15 release evidence

This document is the release-readiness evidence map for SpecificationStore plus deterministic multi-repository orchestration. The authoritative gate is the repository's full CI workflow: every pull request and `main` push runs `pytest -q` on Ubuntu and Windows with Python 3.11 and 3.12.

## Integrated release journey

`tests/test_v015_release_readiness.py::test_v015_integrated_central_store_multi_repo_release_journey` exercises one exact local-only journey:

1. create a central `release-specs@0.15.0` SpecificationStore;
2. register/list/doctor/export context from a coordinating project;
3. resolve the store through the read-only reference contract;
4. declare API, shared, and UI local Git repositories with deterministic requirement/task ownership;
5. build the provider-neutral feature graph and prove requirement → repository ownership → task → PR-reference trace edges;
6. build and execute an all-repository run plan without hidden Git/network mutation;
7. aggregate all-repository verification; and
8. prove the central store did not change and all participant repositories remain clean.

## Negative and adversarial guarantees

The same full CI invocation executes these 0.15 negative gates on every supported OS/Python leg:

| Guarantee | Executable evidence |
| --- | --- |
| conflicting/case-colliding/nested repository authority | `tests/test_multi_repo_authority_hardening_v015.py` |
| unsafe redirects and unavailable participants | `tests/test_multi_repo_authority_hardening_v015.py` |
| overlapping ownership fails closed | `tests/test_feature_repositories_v015.py`, `tests/test_multi_repo_feature_graph_v015.py` |
| stale SpecificationStore content | `tests/test_multi_repo_feature_graph_v015.py`, `tests/test_specification_store_references_v015.py` |
| concurrent store mutation/read consistency | `tests/test_specification_store_references_v015.py` |
| dirty participants and post-plan drift | `tests/test_multi_repo_run_verify_v015.py` |
| fail-fast execution leaves later participants untouched | `tests/test_multi_repo_authority_hardening_v015.py`, `tests/test_multi_repo_run_verify_v015.py` |
| provider metadata is non-authoritative | `tests/test_pr_provider_metadata_non_authoritative_v015.py`, `tests/test_pr_traceability_v015.py` |
| stale/unreachable/cross-feature PR evidence cannot satisfy traceability | `tests/test_pr_traceability_v015.py` |
| organization/core registry locks cannot be weakened | `tests/test_specification_store_registry_v015.py` |
| Unicode/path portability boundaries | `tests/test_feature_repositories_hardening_v015.py`, `tests/test_pr_traceability_portability_v015.py`, `tests/test_multi_repo_authority_hardening_v015.py` |

SpecificationStore references are direct coordinator-to-store bindings. The 0.15 store manifest/reference schemas have no store-to-store reference edge, so a cyclic store-reference graph is not expressible by the contract.
