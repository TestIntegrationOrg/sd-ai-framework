# SDAI 1.0 Mandatory Reference Journeys

Issue: #284

This document defines the release-blocking end-to-end journeys required for SDAI 1.0. The executable gate is `tests/test_v107_reference_journeys.py`; it runs as part of the normal unfiltered `pytest` suite on every supported CI platform.

## Journey A — small feature lifecycle

Proves that a lightweight single-repository feature can move from feature intake and specification truth into isolated implementation, independent specification/code-quality review, fresh completion evidence, and a terminal completed task in the durable execution ledger.

The external provider boundary is deterministic in CI, but the test uses production `AgentRuntime`, isolated-task contracts, persisted stage results, completion policy, completion barrier, and execution-ledger APIs. It therefore validates SDAI orchestration rather than a test-only lifecycle.

## Journey B — critical enterprise lifecycle

Proves the governed critical-feature path across architecture validation, organization policy, isolated implementation/reviews, test/quality/security/approval evidence, completion gating, and convergence.

The organization policy disables architecture waivers. Completion policy strengthens the critical task gate by requiring approval in addition to the built-in critical dimensions. Approval evidence deliberately records `identityBacked: false`: this is a local/manual gate only.

Identity-backed GitHub Enterprise/OIDC/SSO authorization remains explicitly out of scope under #25. This release gate must not be interpreted as cryptographic approver identity, distinct-approver identity enforcement, or external IdP authorization.

## Journey C — genuine multi-repository lifecycle

Proves a central specification store spanning two distinct Git repositories. The test resolves real repository roots, ownership rules, central source-of-truth deltas, cross-repository feature graph edges, local PR trace evidence, deterministic run planning/execution, and all-repository verification aggregation.

It also proves conflict safety: a participant changed after planning causes `revalidate_run_plan` to fail closed instead of running against stale repository state.

## Journey D — interruption and recovery

Proves interruption after a committed workflow side effect, process recreation through `load_execution_run`, checkpoint persistence, dispatch-token reuse for the interrupted leaf, and exact resume to completion.

The completed first leaf is not dispatched again; its terminal ledger event and bound evidence bytes remain unchanged. Every task has exactly one `task.completed` event after recovery.

## Delegated focused coverage

This release gate intentionally composes existing production surfaces instead of repeating all edge cases. Focused suites remain authoritative for malformed/corrupt ledgers and checkpoints, stale artifact detection, parallel/fan-out resume, architecture artifact syntax, policy-layer semantics, PR-evidence conflict cases, multi-repository verification exit classes, and completion-barrier freshness semantics.

## CI release condition

The gate is included by the existing unfiltered `pytest` CI command. SDAI 1.0 release readiness requires the frozen PR head containing this file and `tests/test_v107_reference_journeys.py` to pass the supported matrix:

- Ubuntu — Python 3.11 and 3.12
- Windows — Python 3.11 and 3.12
- macOS — Python 3.11 and 3.12

No journey introduces a production bypass for policy, architecture, traceability, completion, or durable execution state.
