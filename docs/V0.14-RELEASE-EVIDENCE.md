# SDAI 0.14 Release Evidence — Workflow Engine 2

This document is the release-evidence contract for milestone **0.14** / parent issue **#21**. The final gate is issue **#170** and may merge only after the exact candidate head passes the complete repository CI matrix on Ubuntu and Windows with Python 3.11 and 3.12.

## Release objective

0.14 makes advanced orchestration a deterministic, bounded, policy-safe extension of SDAI rather than a provider-specific execution path. Layered workflow sources resolve through non-weakening overlays into one canonical graph; executable leaves bind shell-free or trusted-plugin plans before durable dispatch; the existing execution ledger remains the sole pause, checkpoint, status, and resume authority.

## Integrated reference journey

`tests/test_workflow_engine2_release_gate_v014.py` creates a new repository workflow and PluginStep at test runtime. No provider-specific core branch knows either extension. The positive journey proves:

1. Organization and repository overlays apply in authoritative order and preserve operation-level graph provenance.
2. The resolved v9 graph contains sequence, if, switch, parallel, fan-out, fan-in, foreach, and bounded-while controls.
3. Approval, advisory agent, deterministic, validator, quality-gate, safe-command, and plugin leaves all execute through the same bounded engine.
4. Fan-out plugin execution is explicitly serialized, while read-only parallel branches retain deterministic source-ordered results.
5. Foreach item and bounded-loop iteration identities are finite, stable, and context-bound.
6. The safe command sends a Unicode/metacharacter payload as one argv token, normalizes JSON output, creates no injected file, and binds evidence to the exact plan hash.
7. A repository PluginStep resolves through manifest, publisher, trusted-executor, private-input hash, effective-permission, and policy-source bindings without exposing its secret input.
8. The approval leaf pauses after prior side effects complete; public status identifies the exact next work without serializing private leaf output.
9. Resume reuses the approval dispatch identity, skips all completed plugin and safe-command side effects, then completes the repository overlay's final step.
10. Reopening the completed run returns the checkpointed result without dispatching another leaf, and the final machine status reports a current checkpoint.
11. `workflow graph`, `resolve`, `validate`, and `status` plus the resume library contract emit their versioned canonical JSON forms; the private metacharacter input is absent from every emitted document.

This is the extension-first proof for Workflow Engine 2: a layered workflow and unknown PluginStep are handled by generic graph, policy, planning, execution, and ledger contracts.

## Architecture invariants retained

Workflow YAML remains declarative data. Expressions cannot evaluate arbitrary code; safe commands use executable plus argv and recheck effective policy at execution; PluginStep manifests select only executors already registered by trusted application code. Organization policy and required gates cannot be weakened by repository or user layers.

Workflow Engine 2 does not create a second state database, infer success from conversation memory, replay completed side effects during resume, allow unbounded work, or run workspace writers concurrently without a future governed write-permit contract. Legacy workflow execution remains available for historical schemas, and its compatibility tests remain authoritative.
