## Lifecycle evidence

The full repository test suite exercises the 0.11 lifecycle across durable repository state rather than relying on provider self-reporting:

1. **Requirement truth and deterministic verification** — verify-engine tests build current repository facts, artifacts, trace state, semantic evidence, and typed evidence into `sdai.verify-report/v1`.
2. **Verification to remediation** — convergence tests consume blocking verification findings into stable remediation tasks and persist/reload `sdai.convergence-state/v1` across rounds and resume boundaries.
3. **Fresh implementation invocation** — isolated-task tests bind one remediation task/attempt to explicit context, dispatch identity, Git state, semantic role, allow/deny roots, and immutable contract/result records.
4. **Independent task review** — spec-compliance review must pass before code-quality review; review results are bound to the current worker, task attempt, Git/content state, and predecessor review.
5. **Current completion evidence** — completion-barrier tests reject missing, stale, failed, blocked, previous-attempt, wrong-subject, or worker-self-review proof before task completion.
6. **Whole-change review** — final-review hardening rejects superseded attempts and contracts that do not cover the current ledger task/attempt set.
7. **Re-verification and terminal run state** — change completion requires current final review plus current verification under the resolved durable risk policy; durable ledger transitions are revalidated on reconstruction/resume.
8. **Routing without semantic drift** — routed execution can select a different eligible profile/provider/model while durable semantic identities such as `developer` and `code-reviewer` remain unchanged.

## Acceptance evidence by parent #117

- **Provider-neutral Agent Platform remains authoritative.** Routing selects profiles; semantic agent identity is separate and durable.
- **`sdai verify FEATURE` remains read-only and deterministic.** Verify tests assert byte preservation and stable JSON/exit semantics.
- **Provider evidence is normalized before affecting verification truth.** Semantic-review and trace-evidence contracts carry content/Git bindings and freshness state.
- **Convergence is bounded.** Maximum-round and repeated/unresolved failure paths escalate instead of looping forever.
- **Every remediation task receives independent review.** The sequence is implementation → spec review → code-quality review; final whole-change review is separate.
- **Completion is a framework barrier.** Current task/change evidence is evaluated before terminal transitions, not accepted from agent prose.
- **Policy cannot be weakened by lower layers.** Organization/repository/user policy tests verify intersection/monotonic requirements for profiles, providers, evidence, and completion policy.
- **Routing is deterministic and explainable.** Each candidate records eligibility/rejection reasons; selection is stable across the same inputs.
- **UTF-8 and cross-platform behavior are regression-gated.** 0.11 tests use Unicode paths/content and run under the repository Windows/Linux × Python 3.11/3.12 CI matrix.
- **Crash/resume remains durable.** 0.9 ledger/resume contracts remain in the full regression suite and 0.11 tests cover current-attempt and idempotent retry behavior.
